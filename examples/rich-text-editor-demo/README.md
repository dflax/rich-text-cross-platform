# RichTextEditorDemo

A small multiplatform sample app showing four ways to configure `RichTextEditor`, side by side,
so you can compare them instead of hunting through separate app targets. All four screens run
unchanged on iOS, iPadOS, and macOS — nothing in `RichTextEditorDemo/` is platform-gated.

- **Minimal** — just a `Delta` binding and an `ImageStore`. `allowsImages: false` hides the photo
  button, so this is what a plain text-only editor looks like.
- **With image upload** — a `DemoImageUploader` that "uploads" by copying into a local cache
  directory, so the screen works with no backend at all. In your own app, swap it for a real
  uploader (S3, B2, Firebase Storage, …) — see
  [`docs/guides/getting-started-ios.md`](../../docs/guides/getting-started-ios.md).
- **Custom toolbar** — replaces the default Liquid Glass toolbar via
  `RichTextEditorConfiguration.toolbar`, driving the same `RichTextEditorModel` actions
  (`toggleBold`, `setLineStyle`, …) from a plain text-button bar instead.
- **SwiftData persistence** — the other three screens hold their document in memory only; this
  one actually saves it. `SwiftDataEditorView.swift` has a document list backed by a `@Query`,
  create/delete, and an editor that reads/writes each document's `Delta` through a `StoredDocument`
  model. Create a document, force-quit the app, and it's still there. `RichTextEditorDemoApp.swift`
  has the app-level `.modelContainer(for:)` call this depends on, plus a commented-out block
  showing exactly what changes if you want to sync those documents across devices with CloudKit
  instead of keeping them local to one device.

## Opening and running it

```
open RichTextEditorDemo.xcodeproj
```

Pick a run destination — an iOS/iPadOS Simulator, or "My Mac" — and hit Run. The project targets
`platform: auto` with `supportedDestinations: [iOS, macOS]`, the same shape Apple's own
"Multiplatform App" template produces (one target, not Mac Catalyst, not two separate targets),
matching the package's iOS 26 / macOS 26 minimum deployment target.

`RichTextEditorDemo.xcodeproj` is checked into git (only `project.pbxproj` is tracked; build
state like `xcuserdata/` is gitignored as usual). It's generated by
[XcodeGen](https://github.com/yonaskolb/XcodeGen) from [`project.yml`](project.yml), which keeps
the project definition readable and diffable instead of a hand-edited, merge-conflict-prone
`.pbxproj`. You don't need XcodeGen installed just to open and run the app — only to regenerate
the project after changing it.

## Running on a real iPhone or iPad

Select the `RichTextEditorDemo` target, open Signing & Capabilities, and pick your own team under
"Team." A free personal-team Apple ID is enough for a device you own — no paid Apple Developer
Program membership required.

If Xcode still shows a signing error after picking a team, try Product → Clean Build Folder — a
stale unsigned build can linger. On a fresh device, the first run may also ask you to trust the
developer certificate under Settings → General → VPN & Device Management; that's a normal iOS
step, not specific to this project.

Don't set `CODE_SIGNING_ALLOWED` or `CODE_SIGNING_REQUIRED` to `false` in `project.yml` as a way
to build without picking a team — that forces a permanently unsigned binary no matter what team
you pick afterward. It'll build and run fine on Simulator or "My Mac," then fail to install on a
real device with "The executable is not codesigned." Signing here is left on `Automatic` with no
team hardcoded, which is what lets your own team selection actually take effect. CI passes
`CODE_SIGNING_ALLOWED=NO` on the command line instead, since headless builds have no team to pick.

## Changing the project

If you add, remove, or rename a source file, or edit `project.yml`:

```
brew install xcodegen   # once
xcodegen generate       # from this directory, regenerates RichTextEditorDemo.xcodeproj
```
